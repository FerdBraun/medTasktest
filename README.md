#  Комментарии к выполненному заданию

##  Общие соображения

В рамках выполнения задания возникли некоторые неоднозначности в постановке:

* Из описания не было до конца ясно, требуется ли модификация базы данных.
* Не были детализированы требования к структурам данных.
* Отсутствовало явное описание механизма обработки периодичности запросов.

В связи с этим архитектурные решения принимались самостоятельно, с опорой на предполагаемую логику работы системы.

---

##  Реализация

Для поддержки периодичности задач в модель данных были добавлены два дополнительных поля:

* **Тип периодичности** — определяет формат интервала (например: ежедневно, еженедельно и т.д.)
* **Значение периодичности** — задаёт конкретный интервал

При обработке каждого запроса сервер выполняет проверку: необходимо ли изменить статус задачи, исходя из указанных параметров периодичности.

---

##  Тестирование и отладка

Для упрощения тестирования реализованы дополнительные инструменты:

* **Пользовательский интерфейс (UI)** для управления и наблюдения за задачами
* **Виджет подмены системного времени**, позволяющий эмулировать различные временные сценарии и проверять корректность логики
